BIDeT 4D -- notes for people changing the code
==============================================

HANDOFF.md is the running state of the work (what was done last, what is
untested, the open questions).  This file is the stable part: how the code is
shaped, how to extend it, how it is tested, and what has bitten before.  README.md
is for users; BIF-SPEC.md is the file format.  Counts and dates below are as of
2026-10-12.


1. THE SHAPE OF IT
------------------

    terminal art / text / a .vt session
         |  bifin        importers (READERS): text, lettering, vt
         v
       a BIF  (.bif)     vector + raster layers, palette, grid, frames
         |  bifop        operations (OPS, @op): pen theme crop skew arc wave
         v                extrude spin sway popout motion scroll join overlay ...
       a BIF
         |  bifout       writers (WRITERS, ANIMATED): png gif sixel; or plays it
         v
    PNG / GIF / SIXEL on a terminal

    bidet = bifin | bifop | bifout, built from presets and a few flags.  It is
    SUGAR: it must never do anything the three tools cannot, and `bidet -n`
    prints the pipeline it would run.  tests/test_bidet.py (SugarOverThePipe)
    checks that bidet's bytes equal the real tools' bytes.

    The file             what it is
    bif.py               the BIF library: read, write, validate; `bif.py info|check|chunks`
    bifin.py             tool 1: the command line and READERS
    bifin_text.py        terminal art -> BIF (unascii's reader/classifier by line range + a new assembly)
    bifin_regions.py     art of several kinds at once (text, blocks, line, tone): cut into regions, each drawn its own way
    bifin_lettering.py   a string in a font -> BIF (fonts.py, ttfglyphs.py)
    bifin_vt.py          a terminal session -> an animation (one frame per screen)
    bifop.py             tool 2: the registry and command line; bifop_3d.py, bifop_join.py, bifop_scroll.py register more ops
    bif3d.py             the 3D stage: solid, camera, shadow, paths (pop, spin, sway)
    bifout.py            tool 3: PNG, GIF, SIXEL, playing; bifrender.py draws a frame; bifsixel.py encodes
    bifterm.py           asking the terminal (DA1, OSC 11, CSI 16 t)
    bifgfx.py            the formats that are not an image file or SIXEL: kitty, iTerm2, ANSI art, Tektronix; `auto`
    bidet.py             the front end; presets.ini; gallery.py; timemachine.py
    tonetrace.py         marching squares: tone art as vector lines

    4D does not depend on the legacy ../3D.  Only an optional test uses its SIXEL decoder
    (../3D/gfx-conv/sixeldec.py).


2. HOW TO ADD ...
-----------------

 An importer     A function(data, **options) -> bif.Picture, added to READERS in bifin.py, and its flags
                 in build_parser() / options_of().  bifin_vt.py is the smallest complete example.
                 `convert()` picks one by -f, or by file name (*.vt), or sniffs.

 An operation    @op(name, [(param, converter, default, help)], doc) on a function(pic, notes, **params).
                 Rules: never write into an array (clone() shares them): replace it; compose geometry
                 into the layer's `transform`; anything that breaks the character grid calls drop_grid().
                 Operations in their own module are imported at the bottom of bifop.py, after
                 sys.modules.setdefault("bifop", ...), so that a script run as `python bifop.py` shares one registry.

 An output       WRITERS[name] = (function(rendering, fp, transparent, **options), extensions).  The options are
                 format_options()'s (cols, rows, glyphs, colors, aspect, term, tek_invert) plus pic= and frame=; take what
                 you need and ignore the rest.  If it can move, also ANIMATED[name] = function(renderings,
                 durations_ms, fp, transparent, loop, speed, samples); a format for a terminal is also in TERMINAL_FORMATS
                 (and in PLAYABLE if bifout.play() can play it).  Encoders for the terminal formats live in bifgfx.py, which
                 was ported by copy from ../3D/gfx-conv (tests/test_gfx.py compares the two byte for byte where it is present).

 A kind of region
                 Mixed art (a motd, a neofetch screen) is cut into regions by bifin_regions.plan(): every cell gets one of
                 text / block / line / tone / mix (or None if blank).  import_grid then runs the old method of each kind on
                 a masked COPY of the grid (bifin_regions.masked) with crop off, one shared palette (info["palette"]) and one
                 cell width (_cell_size: the strictest budget), and import_mixed puts the layers together (a repeated id gets
                 "-method"), adds ONE cells layer for the whole grid and crops with bifop.op_crop.  A new kind = a mode in
                 import_grid + a label in plan() + its place in ORDER (bottom first).  Rules that matter: a single-method
                 picture must come out exactly as before (Plan.mixed is False: tests/test_mixed.py::Samples and the parity
                 gate), `auto` only; vt animations settle one mode with classify() and are not cut.  What is prose
                 (text_cells) is a judgement, with the numbers at the top of the module (GAP_*, FLANK, MAX_PUNCT, TINY,
                 PIXEL_SHARE): an English-looking word has 3 letters or more, a vowel, no run of one character, few case
                 changes, clean punctuation; shading made of letters (cloudlinux) and fill (@@@, MMM, 888) must fail.
                 A solid tone / mix piece (one character >= 60% of it: solid_region) is FILLED, not outlined: fill_layer()
                 draws closed even-odd shapes per colour band under everything and import_grid skips the tone outlines for
                 it; `--tone-fill auto|on|off` (auto = art that is solid_region(): one character >= 60% of it, or <= 8 explicit colours; the samples are not, so the parity gate is
                 untouched).  FILL_* are the numbers.
                 `python bifin_regions.py FILE` prints the map; change a number, run it on the motd files
                 (tests/test_mixed.py::Motd uses them in place if ../../../Misc/AsciiArt is there) and test_bifin.

 A preset        A section in presets.ini.  Keys: description, sample, bifin, bifop, bifout, and for 3D:
                 solid (key=value words), motion (pop+hold+spin hold=2.4), uses (presets applied first).
                 Later presets win where they disagree; `solid` keys REPLACE (one `tall`), ops ACCUMULATE.
                 bidet.check_preset() validates it (flags, ops, 3D look, `uses`); gallery.py draws it.

 A material      An entry in bif3d.MATERIALS: (face fill, (back, front) side colours, bevel).

 A change to the file format
                 Write it in BIF-SPEC.md first, then bif.py (read, write, check), then the generator
                 tests/make_testdata.py (`make testdata`), then whoever uses it.  Unknown layers, keys and
                 chunks must pass through every tool untouched.


3. CONVENTIONS
--------------

 * Python 3.7, Pillow 5.4 and numpy 1.16 are the floor.  No newer syntax; for newer library features use
   getattr / try-except (Pillow's quantize(dither=) and enum names are the usual ones).
 * The tests run on three stacks (section 4).  A feature that works on one is not done.
 * Terminal output goes through bifout / bifterm only (bidet also asks the window size of the terminal, to fit a picture
   to it).  Nothing else reads or writes the terminal.
 * Documents describe what was tested.  If a thing has not been tried in a terminal, a font, a Python, the
   document says so.
 * The author keeps a dated copy of a file in BAK/ before editing it (BAK/ is git-ignored).
 * Files written by Windows tools can look executable to Cygwin's git: after editing, check
   `git diff --summary` for "mode change" and put it right (chmod) before committing.


4. TESTING
----------

 make lint          syntax of every program and test, the shell scripts, the man pages (if groff)
                    (tests/test_docs.py also checks that bifop.1 names every operation and parameter, and that
                    bifin.1, bifout.1 and bidet.1 name every long option: add a flag or an operation, document it)
 make test-quick    test_bif 37, test_bifout 47, test_bifterm 22, test_bifin 47, test_lettering 40,
                    test_tonetrace 14, test_bifop 45, test_bidet 38, test_anim 21, test_3d 48, test_scroll 27, test_mixed 61, test_gfx 30, test_docs 11
 make test          those, and a smoke subset of the parity gate (PARITY_QUICK=1: 7 tests, several minutes)
 make test-full     everything, with the full parity matrix (1232 cases, about ten minutes)

 The parity gate (tests/test_parity.py) holds bifin to a FROZEN copy of the old tool
 (tests/reference/unascii_v3.py): block mode exact, tone within 0.6% of the ink, line art within 2% (8% coloured),
 vector letters within 20%.  The limits and their causes are in tolerance(); if one must be widened, measure it and
 write the reason there.

 While developing: one platform and `make test-quick`.  Full runs and other platforms at milestones, or after changing
 numerically sensitive code (rendering, tracing, the fields).

 The three stacks that have been used (they do NOT trace or draw identically):
     Windows      Python 3.11 / numpy 2.2 / Pillow 11
     WSL Ubuntu   Python 3.8  / numpy 1.17 / Pillow 7      wsl -d Ubuntu-20.04 -- python3 tests/...
     Cygwin       Python 3.12 / numpy 2.5 / Pillow 12.3
 What that has already found:
     - Pillow 7 truncates float coordinates, so the line-art parity limits are wider there.
     - On Pillow 12 the tone trace of tone80.txt has an extra faint line along the top edge (0.56 px thick), on the
       0.5 coverage mark.  A test that binarizes at 0.5 flipped all of it at once: test_simplify now compares at 0.2.
     - A test must not read the terminal it runs in: test_size failed in mintty (936 px wide) and nowhere else, because
       the helper passed pixels=None ("ask the real terminal").  Pass explicit values.  Tests set BIDET_NO_QUERY=1.
 When a test fails on only one stack, compare the INTERMEDIATE numbers (vertex counts, ink pixels, an overlay of the two
 drawings) before touching code or a threshold.  Most of the time the code is right and the measurement is fragile.

 Terminal behaviour is tested against a fake terminal and a fake clock (and `auto` against fake replies and environments): tests/test_bifterm.py (a pty), and the player in
 tests/test_3d.py (bytes, order, timing, frame skipping, Ctrl-C cleanup).  Nothing there proves a real terminal
 draws it.  If ../3D/gfx-conv/sixeldec.py is present, SIXEL can be decoded and looked at: do that before blaming a terminal.


5. TERMINALS: WHAT IS KNOWN
---------------------------

 * Asking: DA1 first and alone (a terminal without SIXEL is asked nothing else); then OSC 11 (background) and CSI 16 t
   (cell size) with a second DA1 as the end mark.  Silence counts as "no SIXEL" unless --force.  The conversation is with
   /dev/tty, so it works in a pipe.  POSIX only; elsewhere nothing is asked.
 * Cygwin's own console (tty /dev/cons*) swallows OSC strings on output, so an OSC 11 query never reaches Windows Terminal,
   which does answer it (measured 2026-10-17, Windows Terminal 1.24, Cygwin 3.6.11; native Windows Python in the same tab
   gets the colour in a few ms, Cygwin Python gets DA1 only, for TERM=cygwin and xterm-256color alike; setting the colour
   with OSC 11 works from native Python and not from Cygwin).  bifterm.query() asks DA1 only there and warns once
   (bifterm.cygwin_console, warn_once).  Workaround that was tested: a PowerShell tab, Windows' own
   C:\Windows\System32\OpenSSH\ssh.exe to the machine (name, not localhost), Cygwin sshd gives a /dev/pty: termprobe says
   ANSWERED in ~50 ms, and a live spin animation showed NO noise (so the noise was the unknown colour: transparent
   frames), on cmdesktop and cmlaptop; the user's Windows Terminal profile "Cygwin" has the command line
   c:\windows\system32\openssh\ssh.exe cmlaptop.  An earlier ssh to ::1 failed (the client used then was not recorded; probably Cygwin's ssh in the
   Cygwin console).  termprobe is the tool for telling these paths apart.
   Better workaround, found later: wincygterm (CWPutils/toolbox).  A native Windows Python front-end keeps the
   console raw and forwards bytes; a helper on Cygwin's Python runs bash on a Cygwin pty.  In a Windows Terminal tab
   `tty` is /dev/pty0 and termprobe says ANSWERED in ~50 ms (2026-10-18, Windows Terminal 1.24, Cygwin
   3.7.0-0.590 development snapshot); tvmail works there.  No ssh, no sshd.  A live bidet animation played clean there (tested by the author).
 * A terminal that gives its background gets OPAQUE frames on that exact colour.  One that does not (the Cygwin console)
   gets TRANSPARENT frames: a pixel is painted in its own colour if at least half covered, else left clear.  Blending an edge
   or a shadow with a guessed page made a pale halo on a dark terminal (fixed).  Soft shadows are not drawn there.
 * Playing: all frames are drawn and encoded once on one shared palette of 254 colours, 253 when the page is transparent (no dithering, so still areas do
   not shimmer; it bands smooth gradients), then replayed on a steady clock, skipping frames if the terminal is slow.
   --erase ech (erase the picture's cells first) is the default; bg (SIXEL P2=0) and none exist.
 * mintty: works well, the only terminal tested thoroughly.  Windows Terminal: noise and stale pixels in animations (seen with the colour unknown, i.e. the Cygwin console; with the
   colour known via the ssh workaround above: no noise); --erase bg made it worse.  Others (WezTerm, foot, xterm, mlterm, iTerm2): not tried.  The documents say YMMV.


6. NUMBERS AND DECISIONS WORTH KNOWING
--------------------------------------

 * GIF: a one-colour picture (line art) gets an exact 256-step ramp from ink to page as its palette; anything else one
   palette median-cut from up to 12 sampled frames, no dithering.  Delays are rounded from the running total to hundredths
   of a second (25 ms steps come out 2, 3, 2, 3, not drifting), and never under 2.
 * A .vt session is replayed on bifin_text's terminal emulator and the screen is taken at each newline BEFORE the newline
   is processed, as `slowcat` sleeps before printing it.  Identical neighbouring screens merge.  Style, colour and palette
   are settled once from the fullest screen, so all frames are drawn alike.
 * The 3D stage draws the flat picture at `res` (2) pixels per unit, extrudes it as a stack of perspective-warped
   silhouettes (about 2 per pixel of depth, at most 320), shades the sides by which way the edge faces, and throws a soft
   shadow on the screen plane.  Depth and hover are fractions of the drawing's shorter side.  The first frame of a pop-out is
   the flat picture, to within antialiasing.
 * `tall=` stretches the picture's height by changing the unit aspect, not by an operation, so presets replace it.
 * The time machine is an assembly of the tools: .vt eras (bifin -f vt -m ansi-block), lettering, `motion`, `join`,
   `overlay` (timemachine.py --script prints the shell commands).
 * Presets, the gallery and the pictures: gallery/ is the `media` branch (one commit, replaced by `make media`).
 * v3 quirk kept on purpose (parity): a row of only dashes, or one `x`, is classed as tone and draws nothing.  Test sprites
   need strokes.
 * A black shadow does not show on a black page.  The time machine's page is #262b33.


7. THINGS THAT BITE
-------------------

 * Python is `python3` on Linux, Cygwin and WSL, `python` or `py` on Windows; Git Bash has none.
 * Paths: WSL sees Windows drives as /mnt/d/..., Cygwin as /cygdrive/d/ (here also /home/...).  Git Bash rewrites /mnt paths.
 * An edit script run through a shell heredoc can lose its backslashes; write the script to a file.
 * A commit message with an apostrophe inside `bash -c '...'` is cut off; use `git commit -F file`.
 * `git stash` on a repository with someone else's stash in it: use a different way to compare before/after.
 * `git reflog expire --expire=now --all` also empties the stash reflog; `make prune-media` uses --expire-unreachable.


8. RELEASING
------------

 make dist                       bidet4d-VERSION.tar.gz (VERSION is read from bifin.py)

9. KNOWN GAPS
-------------

 See HANDOFF.md for the full list.  The main ones: APNG / WebP and asciinema input; textures and tiles (they need paint kinds
 in BIF); warps of the solid before extrusion; Python 3.7 / Pillow 5.4 / numpy 1.16 untested;
 live animation untested outside mintty and Windows Terminal; a `make install` check on a real Linux.
