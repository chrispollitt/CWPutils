Exim on u-l.ca:

This server receives mail from cmpi. After the Postfix changes on cmpi, Exim should receive the mail with an envelope sender of chris@u-l.ca.
Exim then delivers this mail to the final recipient (e.g., Google). The IP address that Exim uses for this final hop is what matters for the SPF check.
DNS SPF Record for u-l.ca (Your Responsibility as Domain Owner):

This is where you fix the spf=none. You need a TXT record in the DNS for u-l.ca.
This SPF record must authorize the outbound mail server IP addresses of your Exim server(s) at u-l.ca.
What should be in the SPF record?
If your Exim server (e.g., mail.u-l.ca) has a static IP address, say 192.81.170.8 (the client-ip Google saw), then your SPF record could be:
"v=spf1 ip4:192.81.170.8 -all"
If u-l.ca's MX records point to the same server(s) that send outbound mail, you could use:
"v=spf1 mx -all" (This means "allow servers listed in MX records for u-l.ca to send mail")
If the server sending mail has an A record (e.g., mail.u-l.ca points to 192.81.170.8), you could use:
"v=spf1 a:mail.u-l.ca -all" or simply "v=spf1 a -all" if u-l.ca itself has an A record pointing to the mail server.
If you have multiple outbound mail servers for u-l.ca, list all their IPs or use appropriate mechanisms (a, mx, include).
Example (assuming 192.81.170.8 is the primary outbound IP for Exim on u-l.ca):
In your DNS management for u-l.ca, create/update a TXT record:
Host: @ (or u-l.ca.)
Value: "v=spf1 ip4:192.81.170.8 -all"
(Start with ~all (soft fail) if you want to be cautious during testing: "v=spf1 ip4:192.81.170.8 ~all")
Important: The IP address d66-183-145-34.bchsia.telus.net (your cmpi's external dynamic IP) should NOT be in the SPF record for u-l.ca. All mail is relayed through Exim on u-l.ca, so only Exim's IP(s) need authorization.
